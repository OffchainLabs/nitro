### Added
- Address filter: new `plaintext` hashing scheme for S3 hash-list files. Under this scheme the `hashes` entries are plain `0x`-prefixed 40-hex addresses instead of sha256 hashes, and the `salt` field is ignored.

### Breaking changes
- The address filter now supports multiple S3 hash-list files, each with its own polling interval. The single-file options `--execution.transaction-filtering.address-filter.s3.*` and `--execution.transaction-filtering.address-filter.poll-interval` were removed; configure `transaction-filtering.address-filter.files` in a config file (an array of entries with the former `s3.*` fields plus a per-entry `poll-interval`) or `--execution.transaction-filtering.address-filter.files-list` (a JSON string using the same field names as the config file, with durations as nanosecond integers). An address is filtered if it appears in any configured list; the node only starts (and reports filtering-ready) after every list downloads successfully. Note that `preallocate-memory` defaults to `true` only for `files-list` entries — entries in a config file must set it explicitly. Per-file metrics are exported under `arb/addressfilter/file/<index>/…`, where `<index>` is the entry's position in the `files` array.
