### Added
- Inline genesis: the `init.genesis-json` config option holds a genesis document in the same format as a genesis json file, so a single config file can boot a new chain — in a config file the document can be pasted verbatim as a nested json object (`--conf.dump` prints it back as a json string). The new `init.genesis-mode` option (`inline`, `file` or `directory`) selects the genesis source explicitly; when unset, the first configured source is used, in the order: `init.genesis-json`, `init.genesis-json-file`, `init.genesis-json-file-directory`. Genesis documents supplied by name (file or inline) are now verified to target the configured chain ID and to use `serializedChainConfig`, as directory-discovered ones already were.
