### Added
- Inline genesis: the `init.genesis-json` config option holds a genesis document in the same format as a genesis json file, so a single config file can boot a new chain — in a config file the document can be pasted verbatim as a nested json object (`--conf.dump` prints it back as a json string). The new `init.genesis-mode` option (`inline`, `file` or `directory`) selects the genesis source explicitly; when unset, the first configured source is used, in the order: `init.genesis-json`, `init.genesis-json-file`, `init.genesis-json-file-directory`. The chain ID is now validated once at boot on every start — whatever the database or init source (genesis document, snapshot, existing database), including `--init.then-quit` runs. Directory discovery happens once at config parse time into an internal resolved value, leaving `init.genesis-json-file` untouched; `init.empty` is never silently cleared anymore — explicitly combining `--init.empty` with a discovered genesis is now a config error.
