### Changed
- The address-filter hash list is no longer buffered fully in memory: the S3 object is multipart-downloaded to a temporary file (new `--…s3.download-dir` option, defaulting to the OS temp dir) and stream-parsed straight into the hash store, cutting peak memory during a reload from roughly the object size plus half (raw JSON buffer + decoded hash slice) down to the in-flight download chunks. Every part request is pinned to the HEAD-checked ETag via `If-Match`, so an object replaced mid-download fails cleanly and is retried on the next poll.
